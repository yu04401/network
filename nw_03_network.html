3.1IPアドレスとサブネット 頻出

IPv4アドレスは32ビット。前半の ネットワーク部で「どのセグメントか」、後半の ホスト部で 「その中の何番目か」を表す。この境界を示すのが サブネットマスクであり、 255.255.255.0 のようなドット10進表記と、/24 という プレフィックス長表記は同じものを指す。

CIDR（Classless Inter-Domain Routing）は、 クラスという固定の区切りを廃し、プレフィックス長を任意に取れるようにした考え方。 これにより必要な規模に合わせてアドレスを切り出せるようになった。

ネットワークアドレスとブロードキャストアドレス

  • ネットワークアドレス：ホスト部がすべて0。そのセグメント自体を指す。ルーティングテーブルに載るのはこの形
  • ブロードキャストアドレス：ホスト部がすべて1。セグメント全体への同報用
  • この2つは端末に割り当てられないため、使用可能ホスト数 ＝ 2ホスト部ビット数 − 2

例：192.168.10.100/26 が属するネットワークと、使用可能な範囲は？

  5. 使用可能範囲：192.168.10.65 〜 192.168.10.126（62個）

VLSM と経路集約 頻出

VLSM（Variable Length Subnet Mask）は、 同じアドレスブロックの中で用途ごとに異なるプレフィックス長を使い分ける設計。 端末が100台の拠点は /25、ルータ間リンクは /30、というように過不足なく割り当てられる。

経路集約（サマライズ／集約）は、 連続する複数のネットワークを1本のより短いプレフィックスにまとめて広告すること。

■ 午後での問われ方
  • 「拠点数×必要ホスト数」からアドレスブロックを設計させ、集約可能なように連続割当てにする意図を書かせる
  • 集約のデメリット →「集約範囲内に実在しない経路も含まれてしまい、その宛先パケットを引き受けてしまう」→ 対策は Null0 へのスタティックルート（3.4節）
  • 端末に 169.254.x.x が付いている → DHCPサーバからアドレスを取得できていない。DHCPリレーの設定漏れ、VLAN誤設定などを疑う

フラグメントとパスMTU探索 頻出

送信するIPパケットが出口インタフェースのMTUを超える場合、ルータはパケットを分割（フラグメント）する。 重要なのは再組立てを行うのは最終宛先ホストだけという点。途中のルータは再組立てしない。 そのため断片が1つでも失われると、元のパケット全体が使えなくなる（＝実効的な損失率が上がる）。

3.3ARP と ICMP 頻出

ARP

ARP（Address Resolution Protocol）は、 IPアドレスから同一セグメント内のMACアドレスを求めるプロトコル。 パケットを送るには宛先MACが必要だが、アプリケーションが知っているのはIPアドレスだけ、という溝を埋める。

traceroute の仕組み 頻出

TTL を 1, 2, 3 … と増やしながらパケットを送る。 TTL=1 のパケットは1台目のルータで0になり破棄され、そのルータから ICMP Time Exceeded が返る。 その送信元アドレスが1台目のルータのIPである。TTL=2 なら2台目 —— と繰り返すことで、経路上のルータを順に暴き出す。 最終的に宛先に届いたら、Echo Reply（Windows）または Port Unreachable（UNIX系のUDP方式）が返って終了する。

途中の行が * * * になる理由：そのルータがICMPを返さない設定になっている、 経路上のファイアウォールがICMPを遮断している、レート制限がかかっている、など。 「そこで経路が切れている」とは限らない——この読み方が障害切り分けの設問で問われる。

Smurf攻撃は、送信元IPを標的に詐称した ICMP Echo Request を、ブロードキャストアドレス宛に送る攻撃。 セグメント内の全端末が標的へ一斉に応答するため、少ない攻撃トラフィックが大量の応答に増幅される（リフレクション／アンプ攻撃）。 対策はルータでのディレクテッドブロードキャストの転送禁止と、送信元詐称を防ぐ Ingressフィルタリング／uRPF。

3.4ルーティング 頻出

ルーティングテーブルと転送判断

ルータは受信パケットの宛先IPアドレスをルーティングテーブルと照合し、 ロンゲストマッチ——合致するエントリのうち、最もプレフィックス長が長い（＝具体的な）もの——を選んで、 その ネクストホップへ転送する。合致するものが何もなければパケットを破棄する （L2スイッチがフラッディングするのと対照的）。

同じ宛先ネットワークを複数のプロトコルから学習した場合、AD値の小さい方を採用する。 同一プロトコル内で複数経路がある場合は、そのプロトコルの メトリック （OSPFならコスト、RIPならホップ数）で比較する。AD → メトリックの順で判断する。

フローティングスタティックは、AD値をあえて大きく設定したスタティックルート。 通常時は動的経路（OSPF＝110）が優先され、その経路が消えたときだけ浮上して有効になる。 専用線が主・インターネットVPNが予備といったバックアップ回線の実現に使う。

3.5OSPF 頻出

OSPF（Open Shortest Path First）は、企業内ネットワークで最も使われる リンクステート型ルーティングプロトコル。動作は次の3段階で理解する。

  1. ネイバーを見つける：Helloパケットを交換して隣接関係を確立する
  2. 地図を共有する：LSA を交換し、全ルータが同一の LSDB（リンクステートデータベース）を持つ
  3. 各自で計算する：LSDB に SPFアルゴリズム（ダイクストラ法）を適用し、 自分を根とする最短経路のツリー（SPFツリー）を作ってルーティングテーブルに載せる
「経路を教え合う」のではなく「地図を配って各自が計算する」——ここが距離ベクトル型との決定的な違い。 全員が同じ地図を持つため、矛盾した経路情報によるループが起きにくい。

DR と BDR 頻出

イーサネットのようなマルチアクセスネットワークでは、n台のルータが総当たりで隣接関係を結ぶと n(n−1)/2 組にもなり、LSA の交換量が爆発する。そこで代表者 DR（Designated Router）を1台選び、 各ルータは DR とだけ隣接関係を結んで、DR が全体へ配信する。 DR の障害に備えた副代表が BDR である。

エリアと各ルータの役割 頻出

全ルータが1つの巨大なLSDBを共有すると、規模拡大にともないメモリ・CPU・再計算の負荷が耐えられなくなる。 そこでネットワークを エリアに分割し、LSDBの共有範囲をエリア内に閉じ込める。 エリア間は必ず バックボーンエリア（Area 0）を経由する構造にする。

経路集約 ― どこでできるか 頻出

  • ABR：エリア間の集約（Type3 LSA を集約して他エリアへ広告）
  • ASBR：外部経路の集約（Type5 LSA を集約）
  • エリア内では集約できない。エリア内は全ルータが同一のLSDBを持つ必要があるため、途中で情報を間引けない

集約すると集約範囲に含まれる実在しない宛先のパケットを引き受けてしまうため、 集約を行うルータには集約プレフィックス宛の Null0 スタティックルートを入れ、 該当パケットをその場で破棄してループを防ぐ。

仮想リンク差がつくは、 Area 0 に直接接していないエリアを、他のエリアを経由して論理的に Area 0 へ接続する救済策。 企業合併などでやむを得ず使うが、恒久的な設計としては推奨されない、という文脈で登場する。

■ 午後での問われ方
  • 「ABR／ASBR はどのように選出されるか」→ 選出ではなく、接続構成と設定によって自動的に決まる
  • エリア分割の目的 → LSDBの範囲を限定し、SPF再計算の影響範囲とルータの負荷を抑えるため
  • 1Gと10Gの経路が同じコストになる → 参照帯域幅を変更する
  • OSPFの切替が遅い → Dead 40秒が原因。BFDを併用する／Hello・Deadを短縮する
  • Router ID にループバックアドレスを使う理由 → 物理インタフェースの障害に影響されず、Router IDが変わらないため

参考：IS-IS はOSPFと同じリンクステート型でキャリア網に多い。EIGRP は距離ベクトル型を拡張したシスコ由来のプロトコル。いずれも用語として押さえておけばよい。

3.6BGP 頻出

BGP（Border Gateway Protocol）は、 AS（Autonomous System：単一の管理ポリシーで運用されるネットワークの集まり） どうしを結ぶプロトコル。最短経路を選ぶことより、組織のポリシーどおりに経路を制御することが目的である点が OSPF と根本的に違う。

BGP の基本
項目内容
トランスポートTCP ポート179。ピアは手動設定（自動発見しない）。TCPの信頼性を利用し、変更分だけを送る差分更新
eBGP異なるAS間のピア。通常は直接接続された隣接ルータどうし
iBGP同一AS内のピア。物理的に隣接している必要はなく、ループバックアドレス間でピアを張るのが一般的（経路が冗長化されるため）
AS番号16ビット（0〜65535）と4バイトAS番号がある。64512〜65534 はプライベートAS

iBGP フルメッシュ問題 頻出

BGP には「iBGP ピアから学習した経路を、他の iBGP ピアへは広告しない」というループ防止ルールがある （AS_PATH が同一AS内では伸びないため、これがないとループを検出できない）。 その結果、AS内のすべてのBGPルータどうしをフルメッシュでピアリングしなければ経路が行き渡らない。 n台なら n(n−1)/2 本のピアが必要で、規模が大きくなると破綻する。

パスアトリビュート（経路属性） 頻出

主要な属性と制御方向
属性内容優先されるのは制御できる方向

方向の覚え方 頻出

  • LOCAL_PREF ＝ 出口の制御。自AS内のルータ全員に「外へ出るときはこっちの回線を使え」と指示する。自分で決められるので確実に効く
  • MED ＝ 入口のお願い。相手ASに「入ってくるならこっちから」と伝えるが、相手が従う保証はない（相手はまずLOCAL_PREFで判断するため）
  • AS_PATHプリペンド：自分のAS番号を余分に付け足して経路を「長く」見せ、そちらを選ばれにくくする。MEDが効かない相手にも有効なインバウンド制御

マルチホームと運用

  • マルチホーム：複数のISPと接続して冗長性と経路品質を確保する構成。自組織のAS番号とプロバイダ非依存アドレスが必要
  • トランジット＝対価を払って全インターネット経路を通してもらう関係、ピアリング＝互いの顧客宛経路だけを直接交換する対等な関係
  • フラッピング：経路が上下を繰り返し、その都度アップデートが世界中に伝播して負荷になる現象。 ルートダンプニング差がつくは、 不安定な経路にペナルティを蓄積し、閾値を超えたら一定時間その経路を抑制する仕組み
  • プレフィックスリスト：受信・広告するプレフィックスを制限するフィルタ。 自AS の経路だけを広告し、誤って他者の経路を広告しない（経路ハイジャックの防止）ために必須
■ 午後での問われ方
  • 「回線Aを優先し、障害時のみ回線Bを使いたい」→ アウトバウンドは LOCAL_PREF、インバウンドは AS_PATHプリペンドまたは MED
  • iBGPをループバック間で張る理由 → 物理経路が冗長化されていれば、片方のリンク障害でもピアが切れないため
  • ルートリフレクタを導入する理由 → iBGPのフルメッシュ構成が不要になり、ピア数を削減して設定と負荷を軽減できるため
  • BGPがTCPを使う利点 → 再送・順序制御を任せられ、差分のみの更新で済むため

■ 午後での問われ方
  • ファイアウォールで ICMPv6 を遮断してはいけない理由 → NDP（アドレス解決・ルータ発見）と PMTUD が ICMPv6 上で動作しており、遮断すると通信が成立しないため

  • デュアルスタック環境で「IPv6経路に問題があるのにIPv4なら通信できる」→ 端末がAAAAを優先するため、IPv6側の障害が表面化する
