第6章　NAT・アドレス変換 NAT / NAPT

IPアドレスの枯渇をしのぐために生まれた技術だが、試験で問われるのは 「変換したことによって何が壊れるか」のほうが圧倒的に多い。 IPsecが通らない、内部から自社サイトが見えない、長時間の接続が切れる—— どれもNATテーブルという「一時的な対応表」に依存していることが原因である。 この一点を軸に整理していく。

6.1NAT が必要な理由

IPv4アドレスは32ビット＝約43億個しかなく、IPアドレス枯渇は早くから予見されていた。 実際、IANA が保有する未割当ブロックは2011年に枯渇している。 そこで採られた対策が、組織内では自由に使える「プライベートアドレス」を割り当て、 インターネットへ出るときだけ限られた「グローバルアドレス」に変換するという方式である。

NAT（Network Address Translation）は、 このIPアドレスの書き換えを行う機能。ルータやファイアウォールが担う。

NATがもたらしたもの（両面を押さえる）

  • 利点：グローバルアドレスの消費を大幅に削減できる／内部のアドレス体系を自由に設計でき、 ISP変更時も内部の再設計が不要／外部から内部への通信を開始できないため、結果として攻撃面が減る
  • 代償：エンドツーエンドの透過性が失われる。 送信元アドレスが途中で書き換わるため、アドレスに依存する仕組みが軒並み壊れる（6.5節）
「NATがあるからファイアウォールは不要」は誤り。 NATは外部からの接続開始を防ぐが、内部から開始した通信の戻りはすべて通すため、 マルウェアの外向き通信やC&Cとの交信は素通りする。 アクセス制御はファイアウォールの責務であり、NATの副次効果に頼らない、という整理で問われる。

6.2NAT と NAPT 頻出

両者の違いは「ポート番号まで変換するかどうか」の一点。ここから同時接続可能数の差が生まれる。

NAT と NAPT
NATNAPT（IPマスカレード／PAT）
変換対象IPアドレスのみIPアドレス＋ポート番号
対応関係1対1多対1
同時通信数グローバルアドレスの数までポート番号の数まで（理論上約6万5千セッション）
用途公開サーバの固定対応クライアントのインターネット接続（一般的な形態）
制約アドレスを多く必要とするポート番号を持たないプロトコル（ICMP・ESP・AH）を素直に扱えない
ICMP はどう扱われるのか。ICMP にはポート番号がないため、NAPT ルータは ICMPヘッダの「識別子（Identifier）」フィールドをポート番号の代わりに使って対応づける。 ping が NAPT 越しでも動くのはこの仕組みによる。一方、ESP/AH には代用できるフィールドがないため NAT-T が必要になる（6.6節）。

6.4NATテーブルとタイムアウト 頻出

NATテーブルは、変換の対応関係を保持する表。 NAT／NAPT を行う機器はステートフル（状態を持つ）であり、この表が通信の生命線になる。

エントリが削除される契機
プロトコル削除の契機タイムアウトの目安
TCPFIN／RST による切断を検知したとき、または無通信タイムアウト数十分〜数時間（機器依存）
UDP無通信タイムアウトのみ（切断という概念がないため）30秒〜数分と短い
ICMP無通信タイムアウト数十秒

典型的な障害シナリオ 頻出

「業務アプリで、しばらく操作せずに放置してから操作を再開すると、必ずエラーになる」—— これは無通信状態が続いたことでNATテーブルのエントリが削除され、 再開時のパケットが変換できずに破棄されたことが原因。

対策の書き方：「アプリケーションまたはOSのキープアライブ送信間隔を、 NAT機器のタイムアウト時間より短く設定する」／ 「NAT機器のタイムアウト時間を業務の想定無通信時間より長く設定する」。 どちらの方向からも書けるようにしておく。

NAPTのセッション数上限も設計論点。1台のNAT機器が保持できるエントリ数には限りがあり、 大量の同時接続（多数の利用者、Webページあたりの多数のセッション）でテーブルが溢れると 新規通信ができなくなる。グローバルアドレスを複数用意して分散させる、 機器のセッション上限値を確認する、といった検討が求められる。

6.5NAT の副作用 頻出

ヘアピンNAT

内部の端末が、自社の公開サーバに「グローバルIPアドレス（またはそのFQDN）」でアクセスしようとすると 通信できない——という現象が起きる。パケットがルータまで行き、 同じインタフェースから折り返す形になるためで、多くの機器は既定でこれを許可していない。

アドレスがペイロードに含まれるプロトコル

NATが書き換えるのはIPヘッダとTCP/UDPヘッダだけである。 ところが一部のプロトコルは、データ部（ペイロード）の中にIPアドレスやポート番号を書き込む。 この部分は書き換えられないため、相手はプライベートアドレスを教えられて接続に失敗する。

NATと相性の悪いプロトコル
プロトコル何が問題か
FTP
（アクティブモード）		クライアントが PORTコマンドで自分のIPアドレスとポート番号を通知し、サーバ側から接続してもらう方式。通知される値がプライベートアドレスのため接続できない。パッシブモードならクライアント側から接続するので通る
SIP / H.323SDP（第15章）の中に、音声を受けるIPアドレスとポート番号を記述する。書き換えないと呼制御は成立するのに音声が流れない（無音になる）
IPsec（ESP/AH）ポート番号がないうえ、改ざん検知のため書き換えると認証が失敗する（6.6節）

これらに対応するため、NAT機器は ALG（Application Level Gateway） を備えることがある。ペイロードの中身まで解釈してアドレスを書き換える機能で、 FTP ALG、SIP ALG などと呼ばれる。ただし暗号化された通信では中身が見えないため機能しない。

ログの追跡性

NAPT により多数の利用者が同一のグローバルアドレスを共有するため、 外部のサーバのログには全員が同じIPアドレスとして記録される。 不正アクセスの発信元を特定するには、NAT機器側で「いつ・どの内部アドレスが・どの外部ポート番号を使ったか」 という変換ログを保存しておく必要がある。 時刻の一致が不可欠なので、NTPによる時刻同期がセットで問われる（第18章）。

■ 午後での問われ方
  • 社内から自社サイトが見えない → ヘアピンNAT／スプリットDNS
  • 放置後に再開すると切れる → NATテーブルのタイムアウト／キープアライブ
  • FTPが通らない → パッシブモードに変更する
  • IP電話で発着信はできるが音声が届かない → SDP内のアドレスが変換されていない
  • 不正アクセスの発信元を特定できるようにするには → NAT変換ログの取得と、NTPによる時刻同期

6.6NATトラバーサル 頻出

NATトラバーサルとは、NATを越えられない通信を、なんとか越えさせるための技術の総称。 代表が IPsec の NAT-T と、P2P通信の STUN／TURN／ICE である。

IPsec の NAT-T 頻出

なぜ IPsec は NAPT を通れないのか

  • ESP にはポート番号がない（プロトコル番号50）。NAPTは多重化にポート番号を使うため、複数拠点・複数端末を区別できない
  • AH はIPヘッダまで含めて完全性を保証するため、NATがアドレスを書き換えた時点で認証検証に失敗する。 AHはNATと原理的に併用できない

STUN / TURN / ICE 差がつく

IP電話やビデオ会議、WebRTC のように端末どうしが直接通信したい場合、 双方がNAPTの内側にいると互いのグローバル側アドレスが分からない。これを解決する枠組み。

6.7CGN と IPv6 との関係

CGN（Carrier Grade NAT／LSN：Large Scale NAT） 差がつくは、通信事業者側でNAPTを行い、複数の加入者が1つのグローバルアドレスを共有する方式。 加入者にはグローバルアドレスではなく、共有アドレス空間 （100.64.0.0/10）またはプライベートアドレスが割り当てられる。

CGN がもたらす問題
問題内容
二重NAT家庭内ルータと事業者のCGNで2回NATされる。ポート開放ができず、外部からの接続を要する用途（VPNサーバ、一部のオンラインゲーム）が使えない
ポート枯渇1つのグローバルアドレスを多数の加入者で分け合うため、加入者あたりに使えるポート数が制限される
追跡性同一IPアドレスを多数が共有するため、ポート番号と時刻まで含めた膨大な変換ログがなければ発信者を特定できない
アクセス制限の巻き添えあるサイトが不正利用者のIPアドレスを遮断すると、同じアドレスを共有する無関係な加入者まで遮断される

IPv6 との関係 頻出

  • IPv6 ではアドレスが潤沢なため、原則としてNATを行わない。 エンドツーエンドの透過性が回復し、この章で挙げた副作用の大半が解消される
  • ただし「NATがなくなる＝無防備になる」わけではない。 外部からの通信の制御はファイアウォールで明示的に行う——これが正しい整理
  • IPv4/IPv6 の変換技術である NAT64 / DNS64（第3章）は、 アドレス節約ではなくプロトコル世代をまたぐための変換であり、目的が異なる
■ 午後での問われ方
  • IPv6化のメリットとして「NATが不要になる」→ エンドツーエンド通信が可能になり、 NATに起因するアプリケーションの制約や変換ログ管理の負担がなくなるため
  • PPPoE から IPoE（IPv4 over IPv6）への移行 → MAP-E／DS-Lite ではポート番号の割当てが制限されるなど、CGN と同種の制約が生じる（第7章）
  • NATを廃止する場合に代わりに必要な対策 → ファイアウォールによる外部からの通信の明示的な制御
