第2章　データリンク層（L2） Data Link Layer

午後Ⅱの構成図で最も面積を占める層。フレームがどのポートから出ていくかを決めるルールがすべてであり、 VLAN・STP・リンクアグリゲーションはいずれも「その決め方を制御する仕組み」と捉えると一本の線でつながる。 設問は「そのフレームはどこへ流れるか」「なぜループするのか」「切り替わるまで何秒か」に集約される。

2.1MACアドレスとフレーム

MACアドレス 頻出

MACアドレスは 48ビット（6バイト）の物理アドレス。 上位24ビットが OUI（Organizationally Unique Identifier）＝ IEEE がベンダに割り当てる識別子、下位24ビットがベンダ内での通し番号。 同一セグメント内で相手を特定するためのアドレスであり、ルータを越えると宛先MAC・送信元MACは書き換えられる （IPアドレスは変わらない、との対比で必ず問われる）。

プリアンブル／SFD を除いたフレームサイズは 最小64バイト・最大1518バイト （802.1Qタグ付きなら1522バイト）。さらにフレーム間には IFG（Inter Frame Gap） 12バイト相当の間隔が入る。回線使用率や実効スループットの計算問題では、このオーバーヘッドを含めるかどうかが問題文で指定される。

FCS（CRC）は誤り「検出」であって「訂正」ではない。 誤りを検出したフレームはスイッチが破棄し、再送は上位層（TCP）に任せる。 インタフェースの FCSエラーカウンタの増加は、ケーブル不良・コネクタ不良・デュプレックスミスマッチ・ ノイズ源の存在を示す切り分けの手がかりになる。

MTU とジャンボフレーム 頻出

MTU（Maximum Transmission Unit）は1フレームで運べるデータ部の最大長で、 イーサネットでは 1500バイト。これを超えるIPパケットはフラグメントされる（第3章）。

ジャンボフレームは MTU を 9000バイト程度まで拡大する拡張。 1フレームあたりのヘッダ比率が下がるためオーバーヘッドが減り、CPU割込み回数も減る。 iSCSI・NFS などのストレージ通信、バックアップ、VXLAN などのカプセル化を伴う環境で効果が大きい。

■ 午後での問われ方
  • ジャンボフレームの導入条件→「通信経路上のすべての機器（NIC・スイッチ・ルータ）で同一のMTUを設定すること」。 1台でも非対応だとそこで破棄され通信できなくなる
  • VXLAN／IPsec のカプセル化でヘッダが増える → MTU超過によるフラグメントや破棄を避けるため、 アンダーレイ側のMTUを大きくする（または端末側のMSSを下げる）

2.2スイッチの動作原理

MACアドレステーブルと3つの動作 頻出

L2スイッチの動作は、次の3語で説明できる。この流れを自分の言葉で書けることが、この章の最低ラインになる。

  1. 学習（Learning）：受信フレームの送信元MACアドレスと受信ポート番号の対応を MACアドレステーブルに記録する
  2. 転送（Forwarding）：宛先MACアドレスをテーブルで検索し、該当ポートだけへ送出する
  3. フラッディング（Flooding）：テーブルに宛先がない場合、および宛先がブロードキャスト／未知のマルチキャストの場合、 受信ポート以外のすべてのポートへ送出する

エージングタイムは、学習したエントリを保持する時間。既定は 300秒（5分）が一般的で、 その間に同じ送信元からのフレームを受信するとタイマがリセットされる。 端末を別ポートへ移設した直後に通信できない、といった事象の原因になる。 STPのトポロジ変更時には、この300秒を待たないよう意図的にテーブルを消去する仕組み（TCN）がある（後述）。

コリジョンは、共有媒体で複数が同時送信して信号が衝突する現象。 CSMA/CD（Carrier Sense Multiple Access with Collision Detection）は、 「送信前に他が使っていないか聴く（搬送波検知）→ 衝突を検知したらジャム信号を送り、 ランダム時間待って再送する（バックオフ）」という半二重時代の制御方式。 現在のスイッチはポートごとに全二重で接続するため、コリジョンは発生せず CSMA/CD は使われない。

L3スイッチ 頻出

L3スイッチは、L2スイッチにルーティング機能を統合した機器。 ルータとの違いは実装にある。ルータが汎用CPUでソフトウェア処理し、多様なWANインタフェースと 高度な機能（NAT・VPN・詳細なQoS）を持つのに対し、L3スイッチは専用ASICで転送処理を行うため、 多数のポートを高速（ワイヤスピード）にさばくことに特化している。 構内のVLAN間ルーティングはL3スイッチ、拠点間・インターネット接続はルータ、という役割分担で図が描かれる。

2.3VLAN 頻出

VLAN（Virtual LAN）は、1台の物理スイッチを論理的に複数のスイッチに分割する技術。 分割の実体はブロードキャストドメインの分割であり、異なるVLAN間はL3を経由しないと通信できない。

VLAN導入の目的（記述の定番）

  • ブロードキャストトラフィックの削減：不要な範囲までブロードキャストが広がらない
  • セキュリティ：部署・用途ごとに分離し、L3で相互通信を制御（フィルタリング）できる
  • 物理配置からの独立：フロアが違っても同一セグメントにでき、レイアウト変更に設定変更だけで追随できる
  • 障害の局所化：ブロードキャストストームなどの影響範囲を限定できる

ポートVLAN と タグVLAN

  • ポートVLAN：ポート単位でVLANを割り当てる方式。そのポートに接続した端末は自動的にそのVLANに属す。 1ポート＝1VLANなので、VLANを増やすほどスイッチ間を結ぶケーブルが必要になる
  • タグVLAN：フレームにVLAN識別子（タグ）を付けて、1本のリンクで複数VLANを運ぶ方式。 標準は IEEE802.1Q

ネイティブVLANは、トランクポートでタグを付けずに送受信するVLAN。 受信時にタグのないフレームが来たら、このVLANのものとして扱う。 リンク両端でネイティブVLANの設定が食い違うと、本来分離しているはずのVLAN間でフレームが混ざる（VLANリーク）ため、 設定不一致はセキュリティ事故の原因になる。

2.4ループとスパニングツリー（STP） 頻出

なぜループが致命的なのか

L2フレームには TTL のような生存期間フィールドがない。これがすべての原因である。 ルータならTTLが0になって破棄されるが、L2ではループしたフレームは永久に回り続ける。

  1. ブロードキャストストーム：ブロードキャストがループ内で増殖し、帯域とスイッチのCPUを枯渇させる
  2. MACアドレステーブルのフラッピング：同一の送信元MACが複数のポートから届くため、テーブルが書き換わり続け、正常な転送ができなくなる
  3. 同一フレームの重複到達：受信側が同じフレームを何度も受け取り、上位アプリケーションが誤動作する

STP の考え方

STP（Spanning Tree Protocol / IEEE802.1D）は、 物理的にループしている構成を、論理的にループのないツリー構造にするプロトコル。 一部のポートを意図的にブロッキングしてフレームを通さず、 障害時にはそのポートを開放して経路を切り替える。 つまり冗長構成を保ちつつ、平常時はループを作らないための仕組みである。

スイッチ間では BPDU（Bridge Protocol Data Unit）という 制御フレームを Hello 2秒間隔で交換し、これをもとに全スイッチが同じツリーを計算する。

ステップ1：ルートブリッジを決める

ツリーの頂点になるスイッチを ルートブリッジという。 ブリッジIDが最も小さいスイッチが選ばれる。

ステップ2：各スイッチでルートポートを1つ決める

ルートポートは、ルートブリッジへ最も「近い」ポート。近さは パスコストの合計で測る。

パスコスト（IEEE802.1D-1998 / short 方式）
リンク速度10Mbps100Mbps1Gbps10Gbps
コスト1001942

同点だったときの決定順序（タイブレーカ）

  1. ルートパスコストが小さい方
  2. それが同じなら 隣接（送信元）ブリッジIDが小さい方
  3. それも同じなら 隣接スイッチの送信ポートIDが小さい方
  4. 最後に自分の受信ポートID
ポイントは3番。2本のリンクで同じ隣接スイッチと繋がっている場合、①②が同点になるため 「相手側の」ポートIDで決まる。自分のポート番号ではない、というのが典型的な引っかけ。 ポートID＝ポートプライオリティ（既定128）＋ポート番号。

ステップ3：セグメントごとに指定ポートを1つ決める

指定ポート（Designated Port）は、リンク（セグメント）ごとに 「そのセグメントへフレームを送出する役割」を持つ側のポート。ルートブリッジのポートはすべて指定ポートになる。 ルートポートでも指定ポートでもない残りが 非指定ポートで、これが ブロッキング状態になりループを断つ。

TCN（トポロジ変更通知）

経路が切り替わると、各スイッチが持つMACアドレステーブルは古い経路の情報のままになる。 エージングタイム300秒を待っていては通信が復旧しないため、 TCN BPDUを下流からルートブリッジへ向けて送り、 ルートブリッジが TC フラグを立てた BPDU を全体に配布する。 これを受けたスイッチはエージングタイムを一時的に Forward Delay（15秒）へ短縮し、 古いエントリを速やかに消して学習し直す。

2.5RSTP と STP の保護機能

RSTP 頻出

RSTP（Rapid STP / IEEE802.1w）は、STP の30〜50秒という収束時間を 1秒程度まで短縮した改良版。高速化を実現している要素は次の3つ。

  1. 代替ポートの事前計算：代替ポート（Alternate Port）を 「ルートポートの予備」としてあらかじめ決めておき、障害時は待ち時間なしで即フォワーディングに昇格させる。 指定ポートの予備はバックアップポートと呼ぶ
  2. プロポーザル／アグリーメント：隣接スイッチ間で「このポートを転送状態にしてよいか（Proposal）」 「よい（Agreement）」という同期ハンドシェイクを行い、合意が取れた区間から順に転送を開始する。 タイマ待ちではなく明示的な合意で安全を確保するのが本質
  3. BPDUの扱いの変更：各スイッチが自分で Hello ごとに BPDU を送出し、 3回連続で受信できなければ即座に障害と判定する（Max Age 20秒を待たない）

ディスカーディングは、STP のブロッキング・リスニング・（ダウン状態）をひとつにまとめた状態。 「転送も学習もしない」という点でまとめられる。状態が4つから3つに減ったこと自体が、 無駄な待機状態を廃したことの表れである。

MSTP と PVST+

  • PVST+：VLANごとに独立したSTPインスタンスを動かす。VLANごとにルートブリッジを変えることで 冗長リンクを負荷分散できるが、VLAN数が増えるとCPU負荷とBPDU量が膨れ上がる
  • MSTP（IEEE802.1s）差がつく： 複数のVLANをひとつのインスタンスにまとめてSTPを計算する。 「VLAN1〜50はインスタンス1、51〜100はインスタンス2」のようにグループ化することで、 負荷分散を実現しつつインスタンス数を抑える。同一のリージョン名・リビジョン・VLAN対応表を持つ機器どうしが同一リージョンとして動作する

ループ検知フレームスイッチが独自の検査フレームを送出し、自分に戻ってきたらループと判断してポートを閉塞STPを動かしていない末端（島ハブの誤接続など）でのループ対策
■ 午後での問われ方
  • 「BPDUガードとループガードの違い」→ BPDUガードは"来てはいけないBPDUが来た"、ループガードは"来るべきBPDUが来なくなった"ときに働く。真逆のトリガと覚える
  • ポートファストをスイッチ間リンクに設定してはいけない理由 → ループが発生するため。だから BPDUガードとセットで使う
  • STPからRSTPへ変更する理由 → 「障害発生時の切替時間を約50秒から1秒程度に短縮でき、業務通信の断時間を許容範囲に収められるため」
  • ストームコントロールの限界 → 閾値内のトラフィックは通るため、ループの根本解決にはならない

2.6リンクアグリゲーションとスタック 頻出

リンクアグリゲーション（LAG）

リンクアグリゲーションは、複数の物理リンクを束ねて1本の論理リンクとして扱う技術 （IEEE802.3ad → 現在は IEEE802.1AX）。束ねたものを LAG と呼ぶ。 得られる効果は2つ。

  • 帯域の拡張：1Gbps × 4本 ＝ 論理4Gbps
  • 冗長化：1本が切れても残りで通信継続。論理的には1リンクのままなので STP の再計算が起きず、瞬断で済む

LACP（Link Aggregation Control Protocol）は、 LACPDU を交換して動的に束ねるプロトコル。設定不一致や片方向障害を検知して、 問題のあるリンクを自動的に束から外せるため、固定設定（スタティック）より安全とされる。 片側を Active、対向を Passive にすることもできる（両方 Passive では成立しない）。

ハッシュ分散 ― 最重要の落とし穴

束ねた複数リンクへの振り分けは、送信元／宛先のMACアドレス、IPアドレス、ポート番号などのハッシュ値で決まる。 同じフローのフレームは必ず同じ物理リンクを通るようにするためで、 これによりフレームの到着順序の入れ替わりを防いでいる。

スタック 頻出

スタックは、複数の物理スイッチを専用ケーブルで接続し、 1台の論理スイッチとして動作させる技術（シャーシ仮想化とも呼ぶ）。 管理IPアドレスも設定も1つになり、運用が大幅に簡略化される。

スタック構成の効果

  • 管理の一元化：構成情報が1つ。設定変更・ファームウェア更新の対象が減る
  • 複数筐体をまたぐLAGが組める：下位スイッチから見ると相手は1台なので、 2台のスイッチに分けて接続しても1本の論理リンクになる
  • STPが不要になる：物理的には冗長構成でも、論理的に1台×1リンクとなりループが存在しない
  • 切替が高速：STPの再計算を伴わないため、片系障害でも数秒以内（LAGのメンバ減少として処理）

MLAG差がつくは、2台のスイッチが 制御は独立させたまま、下位機器からは1台に見せて筐体をまたぐLAGを組む方式。 スタックと違い片方のソフトウェア更新や障害がもう一方に波及しにくいという利点がある一方、 設定と運用は複雑になる。

■ 午後での問われ方
  • 「LAGにしたのに速度が上がらない」→ ハッシュ分散により単一フローは1リンクしか使えないため
  • スタック採用の理由 → 「複数筐体にまたがるリンクアグリゲーションが構成でき、STPを使わずに冗長化と帯域の有効活用を両立できるため」
  • スタックのリスク → 論理的に1台なので、ソフトウェア更新時は全体が再起動対象になる／設定ミスが両系に及ぶ（＝ここが MLAG との比較軸）
  • LACP を使う理由 → 設定不一致や片方向障害を検出し、異常なリンクを自動的に束から除外できるため
