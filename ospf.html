01位置づけと基本原理

OSPF は AS 内部の経路制御を担う IGP（Interior Gateway Protocol）で、IP プロトコル番号 89 で直接動作する。TCP／UDP を使わないため、再送や順序保証はプロトコル自身が実装している。

リンクステート型とは何が違うのか

距離ベクトル型（RIP）は「隣から聞いた経路の伝聞」を中継する。自分より先のトポロジは知らないまま、隣が言う距離を信じて足し算するだけなので、経路が消えたことに気づくのが遅れ、ルーティングループが発生しやすい。

リンクステート型は逆で、各ルータが自分の接続情報（LSA）だけをエリア全体に配り、全員が同一の LSDB（リンクステートデータベース＝ネットワークの地図）を持つ。地図が全員一致していれば、各自が独立に最短経路を計算しても矛盾は起きない。これがループに強い理由である。

方式の比較
観点距離ベクトル型（RIP）リンクステート型（OSPF）
持つ情報宛先ごとの距離と方向ネットワーク全体の地図（LSDB）
広報するもの自分の経路表そのもの自分のリンク状態（LSA）のみ
計算方法受け取った距離に加算ダイクストラ法で自力計算
メトリックホップ数（最大15）コスト（帯域幅ベース）
収束遅い・ループしやすい速い・ループに強い
負荷小CPU／メモリを消費する

最後の行が、次章のエリア分割へつながる。LSDB が大きくなるほど SPF 計算の負荷が上がるため、規模を分割して抑える仕組みが必要になる。

経路表ができるまで

  1. Hello でネイバーを発見する
  2. LSA を交換し、LSDB をエリア内で同期する
  3. LSDB に対して SPF アルゴリズム（ダイクストラ法）を実行し、自分を根とする SPF ツリーを作る
  4. ツリーから最小コストの経路を取り出し、経路表へ登録する

LSDB はエリア内の全ルータで同一だが、SPF ツリーはルータごとに異なる。同じ地図から、各自が自分の現在地を起点に経路を引くためである。

ネイバーになるための一致条件

以下が 1 つでも食い違うと隣接は上がらない。障害切り分け問題では、この表を順に潰していくのが定石。

  • エリア IDが一致していること
  • サブネット（マスク）が同一であること
  • Hello / Dead インターバルが一致していること
  • 認証の方式と鍵が一致していること
  • スタブフラグが一致していること
  • Router ID が重複していないこと
TIMER

Hello は既定 10 秒間隔、Dead インターバルはその 4 倍の 40 秒。Dead を待つ限り検知に最大 40 秒かかるため、高速な障害検知が要件なら BFD を併用するか、タイマ自体を短縮する。タイマは両端で一致させる必要がある。

03DR / BDR

なぜ代表を立てるのか

イーサネットのようなマルチアクセスセグメントで n 台が全組み合わせで隣接すると、隣接関係は n(n−1)/2 本になり、同じ LSA が何度も往復する。そこで代表を立て、DROTHER は DR および BDR とだけ隣接する。隣接数は 2n−3 本に減る（DR–BDR が 1 本、残り n−2 台がそれぞれ 2 本）。

CAUTION — 何が減っているのか

減るのは LSDB を同期する相手の数であって、データの通り道ではない。DROTHER 同士は同一セグメント上にいるため、実際のパケットは今までどおり直接届き、DR を経由しない。DR が担うのは地図の配布業務だけである。

また、隣接しない DROTHER 同士も Hello の交換は続けている。ネイバー（2WAY 以上＝相手を認識している）と隣接（Full＝LSDB を完全同期している）は別概念であり、記述問題では使い分けが求められる。

隣接関係の本数
構成一般式4 台8 台内訳（4 台の場合）
DR なし（全ペア Full）n(n−1)÷2628全 6 通りの組み合わせ
DR / BDR あり2n−3513DR–BDR、DR–A、DR–B、BDR–A、BDR–B

台数が増えるほど差が開く。片方は二次関数的に、もう片方は線形にしか増えないためである。

BDR を置く理由

削減だけなら DR 1 台で足りる。BDR が必要なのは、DR 障害時に選挙をやり直すと、その間セグメント全体の LSA 配布が止まるためである。BDR は DROTHER からの更新（224.0.0.6 宛）を常に受信しており、DR と同一の LSDB を保持している。ゆえに再同期なしで即座に代役を務められる。「受信はするが配布はしない」という非対称が要点。

選出シナリオ ── 何がどの順で決まるか

選出は瞬時に終わるものではなく、タイマ待ち → 候補の絞り込み → BDR 選出 → DR 選出という順序を踏む。次の 4 台を例に追う。

R111.1.1.1既定値
R212.2.2.2既定値
R3103.3.3.3最高値
R404.4.4.4選出対象外

① Wait Timer ── 40 秒待つ理由

インタフェース起動後すぐには選出しない。Dead インターバルと同じ 40 秒、Hello を送りながら待機する。既に DR が存在するセグメントに後から参加した場合に、それを知らずに名乗り出るのを防ぐためである。この待ち時間があるため OSPF の隣接確立は起動直後が遅く、point-to-point 化はこの 40 秒を省く施策でもある。

② BDR を先に選ぶ ── 直感に反する点

「DR を決めてから次点を BDR にする」と考えがちだが、RFC 2328 の手順は BDR → DR の順である。DR 選出の対象は自分が DR だと表明しているルータに限られるため、起動直後は候補が空になる。そこで先に BDR を決め、DR 表明者がいなければ BDR を昇格させる、という手順で必ず埋まるよう設計されている。

図の②で R3 が BDR にならないのは、R3 が既に DR を表明しているためである。

③ 同値のときの決着

R1 と R2 はともに priority 1。ここで Router ID の大きい 2.2.2.2 の R2 が BDR となる。

構成図を渡されたら次の順で機械的に処理する。① priority 0 のルータに × をつける　② 残りの最高 priority、同値なら Router ID 最大 → DR　③ その次点 → BDR　④ 「増設した」「後で接続した」という時系列の記述があれば、交代していないことを疑う。

選出のルールと「設定方法」

「このルータを DR にする」というコマンドは存在しない。できるのは選出結果を誘導することだけである。

手段1 ── プライオリティ（インタフェース単位）

interface GigabitEthernet0/0
 ip ospf priority 100
値挙動
0選出対象から完全に外れる（永久に DROTHER）。低スペック機を確実に除外したいときに使う
1既定値
2–255大きいほど DR になりやすい

手段2 ── Router ID（同値のときの決着）

プライオリティが同じなら Router ID の大きい方が勝つ。Router ID の決定順序は次のとおり。

  1. router-id コマンドによる明示指定
  2. 最大のループバックインタフェースの IP アドレス
  3. 最大の物理インタフェースの IP アドレス
router ospf 1
 router-id 10.0.0.1

実務ではループバックを使う。物理インタフェースだとリンクダウンで Router ID が変わり、OSPF プロセス全体が再起動しかねないためである。

手段3 ── そもそも選出させない

対向 2 台のリンクで DR を選ぶ意味はない。ネットワークタイプを変更すると選出プロセス自体が消える。

interface GigabitEthernet0/0
 ip ospf network point-to-point   ! DR選出なし・Wait Timer なしで即隣接
ネットワークタイプ
タイプDR 選出用途
broadcastあり3 台以上のイーサネットセグメント
point-to-pointなし対向 2 台のリンク。収束高速化の常套手段
non-broadcast（NBMA）ありフレームリレー等。neighbor の手動指定が必要
TRAP — プリエンプトしない

高プライオリティのルータを後から追加しても DR は交代しない。既存の DR が落ちるまでそのままである。反映させるには OSPF プロセスのクリア、またはインタフェースのフラップが必要。「設定したのに DR にならない」障害の大半がこれ。

TRAP — 昇格の順序

DR が落ちたとき、選挙はやり直さない。BDR がそのまま DR へ昇格し、そのあとで残りの DROTHER から新しい BDR を選ぶ。BDR を置く目的が「選挙時間の省略」なので当然の挙動。

選出後の情報交換 ── 初回同期

DR / BDR が決まってからが本番である。まず初回の LSDB 同期があり、それが終わると変化時のみ更新が流れる運用状態へ移行する。

OSPF パケットの 5 種類
Type名称役割
1Helloネイバー発見と維持、DR / BDR 選出
2DBD（DD）LSDB の目次。LSA のヘッダ情報だけを載せる
3LSR不足している LSA の要求
4LSULSA の実体を運ぶ
5LSAck受領確認

なぜ目次から始めるのか

全 LSA を送り合うと、既に保持している情報まで転送することになる。そこで DBD でヘッダ（Link State ID・シーケンス番号・LS Age）だけを交換し、自分が持っていないもの、または古いものだけを LSR で要求する。差分同期の仕組みである。

新旧の判定は シーケンス番号 → チェックサム → LS Age の順で行う。

POINT — LSAck が必要な理由

OSPF は TCP を使わないため、再送と順序保証をプロトコル自身が持つ。LSAck が返らなければ LSU を再送する。信頼性を自前で確保している点が、TCP179 を使う BGP との構造的な違いとして問われる。

運用状態での更新

同期完了後は、リンク状態に変化があったときだけ LSU が流れる。DROTHER が 224.0.0.6 で DR へ送り、DR が 224.0.0.5 で配り直す（本章前半の図を参照）。BDR も受信しているが、DR が正常な間は配布しない。

LSA に関するタイマ
名称既定値意味
LSRefreshTime30 分変化がなくても LSA を再送出し、「まだ有効」であることを示す
MaxAge60 分この LS Age に達した LSA は無効として破棄される
SPF ホールドタイム機種依存短時間に連続して SPF 計算が走るのを抑制する
TRAP — 定期リフレッシュは経路更新ではない

30 分ごとの再送出は「LSA が生存していること」を示すためのものであり、経路表を作り直しているわけではない。SPF 再計算が走るのは LSDB の内容が実際に変化したときだけ。RIP のように定期的に経路表を配り直す方式と混同しないこと。

SPF 再計算のトリガ

  • 新しい LSA を受信し、LSDB の内容が変わったとき
  • 自身のインタフェースがアップ／ダウンしたとき
  • ネイバーとの隣接が切れたとき（Dead インターバル満了、または BFD 検知）
  • DR / BDR が変化し、Type2 が作り直されたとき

逆に言えば、トラフィック量が増えても輻輳が起きても SPF は再計算されない。OSPF が見ているのはトポロジと設定コストだけであり、実際の負荷状況は経路選択に反映されない。これが、動的な負荷分散には別の仕組み（LB、SD-WAN、ポリシーベースルーティング）が必要になる理由である。

確認コマンド

show ip ospf neighbor    ! State欄: FULL/DR, FULL/BDR, 2WAY/DROTHER
show ip ospf interface   ! 自分の役割・priority・DR/BDR の Router ID
show ip ospf database    ! LSDB の中身。LSAタイプ・Adv Router・シーケンス番号

show ip ospf database で見えるシーケンス番号と LS Age を隣のルータと突き合わせれば、同期が取れているかを確認できる。値が食い違ったまま収束しない場合は、MTU 不一致や片方向通信を疑う。

04エリアと ABR / ASBR

DR・ABR・ASBR が混同されやすいのは、この三つが同じ階層の役割ではないためである。見ている境界の大きさが違うだけだと理解すれば区別は容易になる。

三つの役割の決まり方
役割どこの境界か何をするか決まり方
DR/BDRひとつのセグメント内代表として LSA を集約・配布選挙（priority → Router ID）
ABRエリアとエリアの間エリア間経路を Type3 で渡す接続構成で自動的に決まる
ASBRAS と外部の間外部経路を Type5 で持ち込む再配布設定を書いた時点で決まる
POINT

ABR / ASBR に「選定」の手続きは存在しない。設定した結果として自動的にそうなる肩書きである。また DR はインタフェース単位の役割なので、1 台が「セグメント A では DR、セグメント B では DROTHER」となることが普通に起きる。ABR / ASBR は装置単位の肩書き。

ABR になる条件

複数のエリアに属するインタフェースを持つこと。下の 2 行を書いた瞬間に ABR となる。

router ospf 1
 network 10.0.0.0 0.0.0.255 area 0
 network 10.0.1.0 0.0.0.255 area 1

厳密には RFC 2328 の定義上、エリア0 に接続していることが条件に含まれる。エリア1 とエリア2 だけに繋がるルータは、エリア間経路がバックボーンを経由しなくなるため正しく機能しない。物理的にエリア0 へ届かない拠点の救済策が仮想リンクである。

ASBR になる条件

OSPF 以外の経路を OSPF へ再配布する設定を入れること。

router ospf 1
 redistribute static subnets      ! これで ASBR になる
 default-information originate    ! デフォルトルート注入も同様

判定基準は「外部と繋がっているか」ではなく「外部経路を OSPF に持ち込んでいるか」。インターネット接続があっても再配布していなければ ASBR ではない。

他のルータはどう知るのか

Type1（ルータ LSA）のフラグビットで通知される。

ビット意味
B自分は ABR である
E自分は ASBR である
V仮想リンクの端点である

冗長構成では複数台が同時に ABR / ASBR になる

DR と違い「1 台だけ」という制約がないため、冗長化のため 2 台並べるのが一般的。役割の兼任も普通に起こる（エリア0 とエリア1 に接続し＝ABR、スタティックを再配布し＝ASBR、配下 LAN で DR、という 1 台）。

05LSA タイプ

「誰がどの LSA を出すか」が、そのまま役割の定義になっている。この対応を押さえると、前章までの話が一本につながる。

主要な LSA タイプ
Type名称生成するのは伝わる範囲内容
1ルータ LSA全ルータ同一エリア内自分のリンクとコスト、B/E/V ビット
2ネットワーク LSADR のみ同一エリア内セグメントに接続するルータの一覧
3サマリ LSAABR他エリアへエリア間のネットワーク経路
4ASBR サマリ LSAABR他エリアへASBR への到達情報

Type2 が必要な理由

Type1 だけでは「私はこのセグメントに繋がっている」という各ルータの自己申告しかなく、誰と誰が同じセグメントにいるのかが確定しない。Type2 がその対応表となり、SPF ツリー上でセグメントを 1 つの疑似ノードとして扱えるようになる。

ここから 2 つの帰結が出る。DR がいなければ Type2 は存在しない（point-to-point 化したリンクでは生成されない）。そしてDR が変われば Type2 は作り直されるため、DR のフラップはセグメント全体の SPF 再計算を招く。安定した機器を DR にすべき理由である。

Type4 の役割

他エリアのルータは Type5 で「外部経路がある」ことは知るが、その経路を配っている ASBR にどう到達するかを知らない。Type1 はエリアを越えないためである。そこで ABR が Type4 で「ASBR はこちら側にいる」と教える。Type5 と Type4 は必ずセットで機能する。

既定値 100Mbps のままだと 100Mbps 以上が全て コスト 1 になり、高速回線を優先できない。auto-cost reference-bandwidth で引き上げるが、ドメイン内の全ルータで同じ値に揃える必要がある。「なぜ 10G 回線ではなく 1G 回線が選ばれたのか」という設問は、ほぼこれが原因。

合計が等しい経路が複数ある場合は ECMP により等コストロードバランスが行われる（既定で最大 4 経路程度、機種依存）。

「本社と支社の両方にインターネット出口があるのに、なぜ支社の通信が本社側へ流れるのか」という障害シナリオは、E2 が内部コストを無視する性質が原因であることが多い。午後Ⅱの定番。

経路選択の優先順位

コストの大小より先に、経路の種別で優先順位が決まる。

  1. エリア内経路（O）
  2. エリア間経路（O IA）
  3. 外部 E1
  4. 外部 E2

したがって、コストが大きくてもエリア内経路がエリア間経路に優先される。

07特殊エリア

末端の拠点が AS 外部の全経路を保持する必要はない。Type5 を止めてデフォルトルートで代替すれば、LSDB とメモリ・CPU を節約できる。これが特殊エリアの目的である。

エリア種別と流入する LSA
種別Type3Type4/5 Type7特徴
通常エリア○○—全ての経路を保持
スタブエリア○×—外部経路はデフォルトルートで代替
トータリースタブ××—エリア間経路も遮断。最小構成
NSSA○×○スタブでありながら ASBR を置ける
POINT — 制約と回避策の因果

スタブエリアは Type5 を通さないため、スタブエリア内に ASBR は配置できない。しかし現実には「支社をスタブにしたいが、その支社にも独自のスタティック経路がある」という要求が生じる。これを解くために、Type7 という専用の LSA を使い ABR で Type5 へ変換する仕組みが NSSA である。制約 → 要求 → 回避策、という因果で覚える。

なお、スタブ系のエリアでは全ルータでスタブフラグを一致させる必要がある。片側だけ設定すると Hello の不一致で隣接が確立しない。第 2 章の一致条件と直結する。

09試験での問われ方

設問のかたち解答の骨子
エリアを分割する目的LSDB の規模と SPF 計算の負荷を抑え、LSA のフラッディング範囲を限定するため
DR を選出する目的隣接関係の数と LSA 交換量を削減するため
priority 0 を設定する理由性能が低い、または経路上不適切な機器を DR の候補から除外するため
point-to-point にする理由DR 選出を不要にし、隣接確立を高速化するため
ループバックを Router ID にする理由物理リンク障害の影響を受けず Router ID を安定させるため
パッシブインタフェースの目的不要な Hello 送信を止め、そのセグメントを経路情報としてのみ広報するため
ABR / ASBR の配置意図選出ではなく設計判断。冗長性・経路集約・障害波及範囲の観点で答える
NSSA を採用する理由外部経路を抑制しつつ、当該エリアに ASBR を配置する必要があるため

収束が遅い原因Dead インターバル待ち。BFD 併用またはタイマ短縮で改善
STRATEGY

DR は「動的に決まる」、ABR / ASBR は「設計者が意図して配置する」。この違いから、DR については選出結果が意図どおりか、ABR / ASBR についてはなぜそこに置いたかが問われる。問われ方が構造的に違うと理解しておくと、記述の方向性を外さない。

10自己確認問題

用語の定義ではなく、フローを描いて説明できるかを基準に判定する。

  1. 同一セグメントに 4 台のルータがある。DR を使わない場合と使う場合で、隣接関係はそれぞれ何本になるか。 DR なし 6 本（4×3÷2）、DR あり 5 本。DR/BDR と他 2 台の組み合わせ。
  2. DROTHER 同士の State が 2WAY のまま止まっている。これは障害か。 正常。DROTHER 同士は隣接せず 2WAY で停止する。DR との間が 2WAY なら異常。
  3. ExStart で停止するとき、まず疑うべき原因は何か。 MTU 不一致。DBD 交換前のマスタ／スレーブ決定で止まる典型例。
  4. 高い priority を設定したルータを追加したが DR が交代しない。理由と対処は。 OSPF はプリエンプトしないため。OSPF プロセスのクリア、またはインタフェースのフラップが必要。
  5. 初回同期でいきなり LSU を送らず、まず DBD を交換するのはなぜか。 DBD は LSA のヘッダだけを載せた目次であり、これを突き合わせることで自分に不足している LSA だけを LSR で要求できる。既に持っている情報の再転送を避ける差分同期のため。
  6. OSPF に LSAck が存在するのはなぜか。BGP との違いは。 OSPF は IP プロトコル番号 89 で直接動作し TCP を使わないため、再送と受領確認をプロトコル自身で実装する必要がある。BGP は TCP179 を使うため信頼性を TCP に任せている。
  7. 30 分ごとの LSA リフレッシュで SPF は再計算されるか。 されない。LSDB の内容が実際に変化したときだけ再計算が走る。リフレッシュは LSA が有効であることを示すための再送出であり、RIP のような定期的な経路表配布とは異なる。
  8. 回線が輻輳している。OSPF は自動的に空いている経路へ迂回するか。 しない。OSPF が参照するのはトポロジと設定コストのみで、実負荷は経路選択に反映されない。動的な負荷分散には LB や SD-WAN など別の仕組みが必要。
  9. DR と BDR はどちらが先に選出されるか。またその理由は。 BDR が先。DR 選出の対象は自分が DR だと表明しているルータに限られ、起動直後は候補が空になる。先に BDR を決め、DR 表明者がいなければ BDR を昇格させることで必ず埋まるようにしている。
  10. 選出前に 40 秒待つのはなぜか。この待ち時間を省く方法は。 既に DR が存在するセグメントに後から参加した場合に、それを知らずに名乗り出るのを防ぐため（Wait Timer）。対向 2 台なら point-to-point 化すれば選出自体が不要になり待ち時間も消える。
  11. priority 1／RID 1.1.1.1、priority 1／RID 2.2.2.2、priority 10／RID 3.3.3.3、priority 0／RID 4.4.4.4 の 4 台。DR と BDR はどれか。 DR は R3（最高 priority）、BDR は R2（priority 同値のため RID の大きい方）。priority 0 の R4 は最初から対象外。
  12. DR が故障した。BDR は何をするか。選挙はやり直されるか。 BDR がそのまま DR へ昇格する。選挙のやり直しはなく、その後 DROTHER から新 BDR を選出する。
  13. 224.0.0.5 と 224.0.0.6 の違いを、送信者と受信者の観点で述べよ。 224.0.0.5（AllSPFRouters）は全 OSPF ルータが受信、DR からの配布と Hello に使う。224.0.0.6（AllDRouters）は DR と BDR のみが受信し、DROTHER が更新を送るときに使う。
  14. Type1 だけでは不十分で Type2 が必要な理由は何か。 Type1 は各ルータの自己申告に過ぎず、どのルータ同士が同一セグメントにいるかが確定しない。Type2 がその対応表となる。
  15. Type5 に加えて Type4 が必要なのはなぜか。 Type1 はエリアを越えないため、他エリアのルータは ASBR への到達方法を知らない。ABR が Type4 でそれを通知する。
  16. あるルータが ABR かどうかは、どこを見れば分かるか。 Type1（ルータ LSA）の B ビット。ASBR は E ビット、仮想リンク端点は V ビット。
  17. 10Gbps と 1Gbps の経路があるのに 1Gbps 側が選ばれた。原因は。 参照帯域幅が既定の 100Mbps のままで、どちらもコスト 1 になっている。全ルータで参照帯域幅を統一して引き上げる。
  18. E1 と E2 の違いを述べ、E2 で起こりうる問題を挙げよ。 E2 は外部コストのみ、E1 は外部コスト＋内部コスト。E2 は内部の距離を無視するため、遠い ASBR が選ばれ通信が遠回りすることがある。
  19. スタブエリアに ASBR を置けないのはなぜか。その回避策は。 スタブは Type5 を通さないため、外部経路を広報できない。回避策は NSSA で、Type7 を使い ABR で Type5 に変換する。
  20. DR・ABR・ASBR を「役割の単位」で区別せよ。 DR はインタフェース（セグメント）単位で選挙により決まる。ABR・ASBR は装置単位で、接続構成および再配布設定により自動的に決まる。
